QEC From Zero

Quantum computers make mistakes about once every thousand operations. Useful algorithms need billions. This guide explains how the surface code closes that gap. Each idea has a toy you can click, and every chart comes from our own simulations.

01 · motivation

Errors are the whole game

The best physical qubits today fail roughly once per 1,000 operations (an error rate around p = 10⁻³). Algorithms worth running, like chemistry simulation or breaking RSA, need millions to billions of operations. Running a billion steps at 10⁻³ each guarantees a wrong answer.

Better hardware alone won't close a gap of a million times or more. Quantum error correction (QEC) spreads one reliable logical qubit across many unreliable physical qubits. Add more physical qubits and the logical qubit gets exponentially more reliable, provided the hardware is already good enough. That "good enough" level is called the threshold.

The goal: turn a 10⁻³ physical error rate into a 10⁻¹² logical error rate, using as few qubits as possible.

02 · the simplest code

Redundancy and parity checks

Classically, the obvious fix is to copy: store 0 as 00000. If one bit flips you still see a clear majority. That's the repetition code. Its distance is d = 5: it takes 5 flips to turn one valid codeword into the other, so it can fix up to 2 flips.

Here's the trick that carries over to quantum: you don't need to read the bits themselves. You only need the parity checks between neighbours: "are bits 1 and 2 the same?" The pattern of failed checks is the syndrome. A decoder turns the syndrome into a guess of what went wrong.

Try it: flip bits, watch the checks

More bits help only if p < 50%

Chance that majority vote fails, computed exactly. Below p = 0.5 each extra pair of bits pushes failures down. Above it, adding bits makes things worse. That crossing is the repetition code's threshold.

03 · what changes for qubits

The quantum twist

Three things make qubits harder than bits:

  1. Two kinds of error. A bit can only flip. A qubit can suffer a bit flip X (|0⟩ ↔ |1⟩), a phase flip Z (|+⟩ ↔ |−⟩), or both at once, Y. Any small, messy error can be broken down into these three. Measuring the checks forces the qubit to pick one of them, so a decoder only ever deals with X, Y and Z.
  2. No copying. The no-cloning theorem forbids copying an unknown quantum state, so "store it five times" is off the table.
  3. No looking. Measuring a data qubit destroys the superposition you were protecting.

The fix for all three is the same: measure only parities, using products of Paulis like XXXX or ZZZZ on a few neighbouring qubits. These are called stabilizers. The encoded state is a +1 eigenstate of all of them, so measuring them reveals nothing about the stored information. They do notice errors: an error that anticommutes with a stabilizer flips its result from +1 to −1.

Each check is measured by an extra measure qubit (also called an ancilla). It interacts with its neighbouring data qubits through a few CNOT gates and is then measured. Only the measure qubits are ever read out.

04 · the leading code

The surface code

Lay d × d data qubits on a grid and colour the squares between them like a chessboard. Red squares measure XXXX, blue squares measure ZZZZ, and half-disc shapes on the edges measure two qubits. Every check only touches its nearest neighbours, which is why the surface code suits real chips: superconducting processors (Google, IBM) can only couple neighbouring qubits.

Below, click a data qubit to cycle its error: none → X → Z → Y. Checks that notice light up yellow. These are detection events.

X check Z check detection event decoder's correction

Things to try. (1) Put an X on a middle qubit: two blue checks light up. (2) Put X on two neighbours in a row: the checks between them cancel and only the ends of the chain light up. (3) Put X along a whole column: nothing lights up, yet the logical qubit has flipped. That's a logical error, and it needs at least d errors.

Point (3) is the key idea. Errors form chains, and a check lights up only at the ends of a chain. A chain stretching from one boundary to the opposite boundary has no ends, so it is invisible, and it acts on the stored information. Those chains are the logical operators: XL runs top to bottom and ZL runs left to right. The shortest one has length d, so a larger code needs more errors to fail.

A distance-d patch uses d² data qubits plus d² − 1 measure qubits: 17 qubits for d = 3, 49 for d = 5, 97 for d = 7. Google's 2024 "below threshold" chip ran d = 7 on 101 of its 105 qubits.

05 · the classical half

Decoding is matching up the dots

The decoder sees only the yellow dots. It has to guess which error chains made them. Each chain has two ends, or one end if it runs into a boundary, so decoding means pairing up the dots with each other or with the boundary.

Low physical error rates make short chains more likely than long ones. So the best guess is the pairing with the shortest total chain length. That's Minimum-Weight Perfect Matching (MWPM), the workhorse decoder (review §5.1). The "Decode" button above runs exact MWPM in your browser. Then it checks whether the leftover error (the real errors plus the correction) is harmless or crosses the whole patch.

Important: the correction doesn't need to match the real errors exactly. If the leftover forms closed loops, those are products of stabilizers and do nothing to the logical qubit. Many different corrections are equally good. This is called degeneracy, and it's what makes quantum decoding different from classical decoding. The decoder fails only when the leftover chain goes from one side to the other.

Try p = 12% at d = 3 several times. Sometimes the matching connects the dots "the wrong way round" and completes a logical chain. Each failure is a decoding error, and how often it happens is the number we measure.

06 · measurements lie too

Errors in time: detectors

Real check measurements are also noisy: a measure qubit can report the wrong bit. A single round of checks can't tell "a data qubit flipped" apart from "the measurement lied". So we repeat the checks every round (roughly d rounds) and look at what changed between rounds.

A detector compares one check's result in consecutive rounds (Fowler §IV). In the toy below, the repetition code runs for 6 rounds. A data error lights the checks on either side from that round on, but the detectors show only the moment it happened: two dots side by side in space. A measurement error flips one result for one round, giving two dots one above the other in time. Decoding becomes matching in space-time, with the same algorithm.

07 · the number everyone quotes

The threshold

Run many simulated shots and count how often the decoder fails. Do it for several distances d and physical error rates p. The curves cross at the threshold pth. Below it, a bigger code is better, and the gain is exponential: roughly pL ≈ A·(p/pth)(d+1)/2. Above it, a bigger code just gives errors more room to spread.

The threshold depends on three things together: the code, the decoder and the noise model. Papers quote very different numbers because they assume different noise models:

Λ (Lambda) is how much the logical error rate drops each time d grows by 2. It's the number hardware teams report. Google's 2024 chip measured Λ ≈ 2.1. In our simulation with superconducting-style noise (SI1000, where measurements are the noisiest step), MWPM gives:

0.10%≈ 8.5≈ 10

So Google's Λ ≈ 2.1 corresponds to p ≈ 0.3% in this model. Each halving of p roughly doubles Λ, and a larger Λ means a smaller code for the same target. Going from Λ = 2 to Λ = 4 halves the distance needed.

Lower is better. Correlated MWPM halves MWPM's error rate at d = 7 for about 3× the time, the best trade on this page. 09 · use the noise you have

Biased noise and the XZZX code

Many qubits, such as spin qubits, trapped ions and cat qubits, suffer mostly Z errors, because they lose phase much faster than they lose energy (T₂ ≪ T₁). The bias is η = pZ/(pX+pY), and η = 0.5 means all three errors are equally likely.

In the ordinary (CSS) surface code, all those Z errors land on the X checks, so half the decoder is overloaded and the threshold drops. The XZZX code applies a Hadamard to every other data qubit, so each check measures XZZX. Same qubits, same wiring, same decoder. Z errors now look like errors on simple repetition codes running diagonally, and the threshold rises toward 50%.

Circuit-level, η = 100

A common trap: a CSS code run as a Z-basis memory looks great under Z-biased noise, because that experiment can only see X errors. Always add up the Z- and X-basis memory failures (bench.py --basis both).

10 · the clock is ticking

Real-time decoding

A superconducting chip produces a new round of syndrome data about every microsecond, indefinitely. If the decoder is slower than that, unprocessed data piles up without limit: the backlog problem (review Appendix A). The computer can't apply a measurement-dependent gate until the decoder catches up.

The fix is a sliding window: decode a few rounds at a time, commit only the oldest part of the window, then slide forward. The uncommitted buffer lets the decoder look ahead before deciding. Our experiment shows how big that buffer needs to be:

On speed: PyMatching decodes a batch of d = 5 shots in about 0.3 µs per round on one laptop core, faster than the 1 µs hardware cycle. The hard part is latency, getting each window's answer back quickly. A single call from Python costs more than 10 µs in overhead alone, which is why real systems run decoders in C++ or on FPGAs and decode several windows in parallel.

11 · beyond storing a qubit

From memory to computation

Everything so far is a memory experiment: hold one logical qubit and check that it survived. Fowler's 2025 notes show how to compute with surface-code patches:

  • Lattice surgery. Merge two patches by measuring checks along their shared edge, then split them again. This measures joint operators like XLXL and builds a logical CNOT. Fowler draws these as 3D pipe diagrams with time running upward.
  • Nearly free Clifford gates. Hadamard, S and CNOT cost little more than moving patches around. The ZX-calculus offers rules for simplifying these 3D layouts.
  • Magic states for T gates. Clifford gates alone can't beat a classical computer. A non-Clifford gate (T) needs a specially prepared magic state, made by "cultivation" or by distillation factories. These factories take up a large share of a real algorithm's qubit budget.
  • Reaction time. Gates that depend on measurement results have to wait for the decoder. That's another reason real-time decoding matters.

Numbers for a pitch, from fits to our own simulations (estimate.py): at p = 10⁻³, reaching 10⁻¹² per round takes d ≈ 19 (uniform circuit noise) to d ≈ 23 (SI1000). That's about 700–1,000 physical qubits per logical qubit. 100 logical qubits, doubled for routing and magic-state factories, come to roughly 150,000–210,000 physical qubits. At p = 2×10⁻³ the count more than doubles.

12 · hands on

Our toolkit

Everything on this page was produced by the qec package in our repo. The pipeline is the same each time: build a noisy circuit (Stim) → get the detector error model (the graph of which faults light which detectors) → sample shots → decode → count failures.

# one experiment, both decoders, with circuit diagrams
.venv\Scripts\python quickstart.py -d 5 --p 0.003 --diagrams

# threshold sweep (any noise model, code variant, decoder)
.venv\Scripts\python bench.py --name mine --noise circuit --decoders pymatching union_find_weighted
.venv\Scripts\python bench.py --name xzzx --noise circuit --bias 100 --variants css xzzx --basis both

# threshold vs bias, real-time windows, qubit-count estimates
.venv\Scripts\python bias_sweep.py
.venv\Scripts\python realtime.py
.venv\Scripts\python estimate.py --stats out\circuit_decoders\stats.csv --p 0.001 --target 1e-12
# in Python
from qec import SurfaceCode, NoiseModel, detector_error_model, make_decoder

code = SurfaceCode(5, variant="xzzx")                  # or SurfaceCode(dx=3, dz=7)
circuit = code.memory_circuit(NoiseModel.circuit(1e-3, bias=10), basis="Z")
dem = detector_error_model(circuit)
dets, obs = circuit.compile_detector_sampler().sample(10_000, separate_observables=True)
pred = make_decoder("pymatching", dem).decode_batch(dets)
print((pred != obs).any(axis=1).mean())                # logical error rate
