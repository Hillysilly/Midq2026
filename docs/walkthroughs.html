The board every walkthrough uses

This is the X-error half of a distance-5 surface code with perfect measurements. Each dot is a check (a Z stabilizer). Each line is a data qubit: an X error on it flips the checks at both of its ends. Lines that touch the thick bars on the left and right flip only one check, which is why a chain of errors can end at a boundary.

The decoder only sees which checks are lit (orange). Its job is to pick a set of lines, the correction (blue), that lights exactly the same checks. The red dashed lines show the real error; the decoder never sees them. If real error plus correction forms a chain from the left boundary to the right one, the logical qubit has flipped and the decoder has failed. Five errors in a row are needed to cross, so any 2 errors should be fixable.

16 checks32 qubits (lines)distance 5uniform error probability p = 0.1 (for BP)
Clustering · Delfosse & Nickerson 2017

Union-Find

Grow a cluster around every lit check. A cluster holding an odd number of lit checks can't be explained from inside, so it keeps growing, half a line per round in every direction, until it merges with another odd cluster (odd + odd = even) or touches a boundary. Then, inside each cluster, build a spanning tree and peel it from the leaves: a lit leaf puts its line into the correction and passes the light to its parent.

On this board every line takes 2 growth steps. Growing clusters are orange; clusters that stopped (even, or touching a boundary) turn blue-grey.

Cost: almost linear in the number of checksParallel: every line grows at once; rounds track the biggest clusterOurs: 5.6 µs/shot at d=5 on one thread, 2–6 rounds from d=3 to 9
Matching · Edmonds’ blossom

Minimum-weight perfect matching

Pair up the lit checks so that the total length of the chains joining them is as small as possible. Any lit check may instead be joined to the nearest boundary. First compute the shortest distance between every pair of lit checks (and to the boundary), then pick the cheapest complete pairing. Blossom does that in polynomial time; this page uses an exact search, which gives the same answer on a board this small.

Exact: always the lowest total lengthCost: O(k³) for k lit checks; sequentialOurs: identical to PyMatching on every shot we tested
Matching · fast and approximate

Greedy matching, then 2-opt

Start with every lit check sent to the boundary. Pairing two checks instead saves (their two boundary distances) minus (the distance between them). Take the pairing that saves most, then the next one whose checks are both still free, and so on. Afterwards, 2-opt looks at every two pairs and swaps partners whenever that shortens the total.

Greedy can grab one attractive pair and leave two checks stranded far apart. Use Find a failure to see it lose to exact matching.

Cost: O(k² log k), simple to build in hardwareNot distance-preserving: 2.1% of two-fault errors fail at d=5 (2-opt: 0.7%)
Precomputed · one memory read

Lookup table

Before any shot arrives, try every error of up to 2 qubits, work out which checks it lights, and store the smallest error for each pattern. At decode time the 16 check bits form an address, and the answer is one memory read. Patterns that need 3 or more errors aren’t in the table, so a real decoder hands them to a fallback.

Speed: one read, the fastest decoder there isMemory grows like nw: 529 patterns here; over a million at d=5 with real circuits
Message passing · min-sum

Belief propagation

Every qubit starts with the prior belief P(error) = 0.1. Each round, every check tells each of its qubits how likely it is to be flipped, given what the check’s other qubits currently believe and whether the check is lit. Each qubit then adds up what its checks said. Qubits above 0.5 are the current guess; red rings mark checks that guess doesn’t explain yet.

The preset has two lit checks on a diagonal. Two equally short explanations exist (around either corner), so BP can’t choose and keeps circling. That’s degeneracy, and it’s why BP needs a partner on the surface code.

Parallel: every message updates at onceAt d=5, p=0.5% only 39% of shots converge
Hybrid · Panteleev–Kalachev, Roffe et al.

BP + ordered statistics decoding

When BP gets stuck, keep its beliefs and use them to sort the qubits from most to least likely to have an error. Then walk down that list and keep each qubit whose line can’t be made from the ones already kept (Gaussian elimination over 0s and 1s). After 16 keepers, exactly one combination of them lights the right checks: that’s the correction.

This is OSD-0. Our Python version also tries swapping in the next few qubits and keeps the lightest answer (combination sweep).

OSD is sequential Gaussian eliminationOurs beats the ldpc library’s: 6.1e-4 vs 1.0e-3 per round at d=5
Hybrid · belief-find, Higgott et al. 2023

BP + Union-Find

Run BP for a few rounds. If it settles, use its answer. If not, turn every qubit’s belief into a growth cost: lines BP thinks are likely fill in 1 step, unlikely ones take up to 4. Then run Union-Find with those costs, so clusters reach along the lines BP pointed at. Both halves are parallel.

Parallel: BP per message, UF per lineOurs ties PyMatching’s correlated mode at d=7: 3.5 per 10,000 rounds
